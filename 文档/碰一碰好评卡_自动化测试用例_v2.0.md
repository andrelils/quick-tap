## 1. 测试概述与环境

### 1.1 系统架构

| 层级 | 技术栈 | 端口/地址 |
|------|--------|-----------|
| 管理后台前端 | Vue 3 + Ant Design Vue + Vite | http://localhost:5174 |
| 后端服务 | Spring Boot + MyBatis + MySQL | http://localhost:8222 |
| C端小程序 | uni-app (H5) | http://localhost:5175 |
| 数据库 | MySQL (远程) | 154.8.138.48:3306 |
| C端生产 API | - | http://154.8.138.48:3000/api/miniapp |

### 1.2 角色体系

| 角色 | 标识 | 权限范围 |
|------|------|---------|
| 超级管理员 | `super_admin` | 全部功能，含推广平台、商家访问权限、系统配置、用户管理 |
| 管理员 | `admin` | 商家、设备、营销、AI 等业务模块（不含超管专属） |
| 商家 | `merchant` | 自身商家信息、设备、AI 创作、营销配置、当前额度 |

### 1.3 测试环境变量

```yaml
env:
  base_url: "http://localhost:8222"           # 后端 API 基地址
  admin_url: "http://localhost:5174"           # 管理后台前端地址
  c_url: "http://localhost:5175"               # C端 H5 地址
  timeout: 15000                               # 默认超时(ms)
  super_admin_username: "andre"                # 超管账号（现有账号）
  super_admin_password: "请填入 andre 的密码"   # TODO: 测试前替换为真实密码
  miniapp_base: "{base_url}/api/miniapp"       # C端 API 前缀（BASE_URL 已含 /api/miniapp）
```

### 1.4 统一响应格式（核心约定）

所有接口统一返回 `ApiResponse<T>`，**`code` 为字符串类型**：

| 字段 | 类型 | 说明 |
|------|------|------|
| code | String | 业务码，成功为 `"1000"` |
| message | String | 提示信息 |
| data | T | 业务数据（仅成功时返回） |
| status | Integer | HTTP 状态码 |
| detail | String | 错误详情（失败时） |
| timestamp | String | ISO-8601 服务器时间 |
| traceId | String | 请求追踪 ID |

**分页响应 `PageResponse<T>` 字段：`list`（非 records）、`pageNum`、`pageSize`、`total`、`totalPage`、`hasNext`、`hasPrev`。**

### 1.5 测试主逻辑（整体流程）

```
1. admin 登录（andre 超管） → 创建一组新设备（QR + NFC） → 拿到 systemCode
2. 用 systemCode 访问 miniapp H5 页面 → 进入注册页 → 提交注册
3. 回 admin 校验：设备列表绑定状态、商家列表新增记录是否正确
4. 商家注册后（待审核）不能登录后台；admin 审核通过后商家可登录
5. 用注册的商家数据回到 C 端详情页，逐个校验详情页所有接口
6. admin 端逐模块巡检：仪表盘、商家、设备、AI、营销、系统设置
7. 测试数据清理（删除 AUTO_TEST_ 前缀数据）
```

## 3. 通用断言规则

```yaml
assertions:
  api_response:
    status: 200                     # HTTP 状态
    code: "1000"                    # 业务成功码（字符串）
    has_data: true                  # 需要 data 时

  error_response:
    code_not: "1000"
    status_in: [400, 401, 403, 404, 409, 500]

  page_response:
    has_field: "list"               # 分页数据在 list 字段
    total_is_number: true

  response_time_lt: 3000            # ms（AI 生成类接口除外）
```

id: E2E-001
module: 端到端
title: "创建设备 → C端注册 → 后台数据联动校验"
priority: P0
type: 端到端测试
tags: [e2e, smoke, core-flow]
preconditions:
  - 后端服务已启动（localhost:8222）
  - andre 超管账号可用
steps:
  # 阶段1：管理端登录
  - description: "超管登录获取 token"
    action: api_request
    method: POST
    url: "{base_url}/api/admin/auth/login"
    body:
      username: "{super_admin_username}"
      password: "{super_admin_password}"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.token"
    not_empty: true
  - action: assert_json_path
    path: "$.data.role"
    equals: "super_admin"
  - action: extract
    path: "$.data.token"
    var: admin_token

  # 阶段2：批量创建设备（QR + NFC 一组）
  - description: "批量创建设备组"
    action: api_request
    method: POST
    url: "{base_url}/api/device/batch"
    headers:
      Authorization: "Bearer {admin_token}"
    body:
      - deviceNo: "AT{t}QR"
        name: "AUTO_TEST_设备_{timestamp}"
        type: "qrcode"
        systemCode: "AT{t}"
        url: "{qrcodePrefix}?q=AT{t}&code=AT{t}"
      - deviceNo: "AT{t}NFC"
        name: "AUTO_TEST_设备_{timestamp}"
        type: "nfc"
        systemCode: "AT{t}"
        url: "{qrcodePrefix}?code=AT{t}"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.total"
    equals: 2
  - action: assert_json_path
    path: "$.data.success"
    equals: 2
  - action: assert_json_path
    path: "$.data.fail"
    equals: 0
  - action: set_var
    var: system_code
    value: "AT{t}"

  # 阶段3：C端绑定校验（未注册 → 未绑定）

    method: GET

      code: "{system_code}"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.bound"
    equals: false
  - action: assert_json_path
    path: "$.data.merchant"
    equals: null

  # 阶段4：C端商家注册
  - description: "商家自助注册"
    action: api_request
    method: POST
    url: "{miniapp_base}/merchant/register"
    body:
      username: "autotest_{timestamp}"
      password: "Auto@123456"
      nickname: "AUTO_TEST_店长"
      merchantName: "AUTO_TEST_商家_{timestamp}"
      contactName: "测试联系人"
      contactPhone: "13800138000"
      code: "{system_code}"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: extract
    path: "$.data.merchantId"
    var: merchant_id

  # 阶段5：后台数据联动校验
  - description: "设备列表按关键字查询，验证绑定状态"
    action: api_request
    method: GET
    url: "{base_url}/api/device/list"
    headers:
      Authorization: "Bearer {admin_token}"
    params:
      keyword: "AUTO_TEST_设备"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.list[0].merchantId"
    equals: "{merchant_id}"
  - action: assert_json_path
    path: "$.data.list[0].bindStatus"
    equals: true
  - action: assert_json_path
    path: "$.data.list[0].qrcode"
    not_null: true
  - action: assert_json_path
    path: "$.data.list[0].nfc"
    not_null: true

  - description: "商家列表查询，验证新商家状态"
    action: api_request
    method: GET
    url: "{base_url}/api/merchant/list"
    headers:
      Authorization: "Bearer {admin_token}"
    params:
      keyword: "AUTO_TEST_商家"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.list[0].id"
    equals: "{merchant_id}"
  - action: assert_json_path
    path: "$.data.list[0].auditStatus"
    equals: 0            # 待审核
  - action: assert_json_path
    path: "$.data.list[0].status"
    equals: 0            # 未启用

  # 阶段6：待审核商家不能登录后台
  - description: "未审核商家登录应失败"
    action: api_request
    method: POST
    url: "{base_url}/api/admin/auth/login"
    body:
      username: "autotest_{timestamp}"
      password: "Auto@123456"
  - action: assert_json_path
    path: "$.code"
    equals: "2005"       # 账号被禁用

  # 阶段7：管理员审核通过
  - description: "审核通过商家"
    action: api_request
    method: PUT
    url: "{base_url}/api/merchant/{merchant_id}/approve"
    headers:
      Authorization: "Bearer {admin_token}"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"

  - description: "审核后商家可登录后台"
    action: api_request
    method: POST
    url: "{base_url}/api/admin/auth/login"
    body:
      username: "autotest_{timestamp}"
      password: "Auto@123456"
  - action: assert_json_path
    path: "$.code"
    equals: "1000"
  - action: assert_json_path
    path: "$.data.merchantId"
    equals: "{merchant_id}"

expected:
  - 设备批量创建成功，QR+NFC 成组
  - C端注册创建待审核商家并绑定设备
  - 后台设备/商家列表数据联动正确
  - 待审核商家不能登录，审核通过后可登录

## 8. 错误码契约

> 错误码定义见 `ErrorCode.java`，HTTP 状态由 `ApiResponse.mapErrorCodeToHttpStatus` 映射。

| 错误码 | 含义 | HTTP | 触发场景 |
|--------|------|------|---------|
| 1000 | 成功 | 200 | - |
| 1001 | 参数无效 | 400 | 必填缺失、格式错误 |
| 1002 | 资源不存在 | 404 | 查询不存在资源 |
| 1003 | 服务器内部错误 | 500 | 未捕获异常 |
| 1006 | 资源已存在 | 400 | 重复创建 |
| 2001 | 未认证 | 401 | 无 token 访问受保护接口 |
| 2002 | token 无效/过期 | 401 | 伪造/过期 token |
| 2004 | 用户名或密码错误 | 401 | 登录失败 |
| 2005 | 账号被禁用 | 401 | status=0 登录 |
| 3001 | 访问被拒绝 | 403 | 角色越权 |
| 4002 | 用户已存在 | 409 | 重复用户名 |
| 5001 | 商家不存在 | 400 | 商家查询失败 |
| 5007 | 设备已注册 | 409 | 重复设备 |
